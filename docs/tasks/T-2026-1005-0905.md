## 方案与边界

候选 A：正式来源宿主增加受限的已登记商品来源，CLI 复用 `prepareMarketingFacts`、完整 G1 证明及 `finalizeMarketingFacts`。优点是 CLI 可直接使用相同事实实现且不依赖数据库服务；代价是命令行工具需要装配宿主来源与审查依赖。

候选 B：CLI 登录正式服务器，经 HTTP API 发起预生产并轮询状态。优点是完全复用服务器生命周期与归档；代价是原本无数据库的批处理工具必须依赖运行服务、租户登录与网络，离线数据审计也需要额外环境。两者均须保留 G1 和最终事实审核。本次选择 A，改动限于已有宿主事实模块和 CLI 接线，正式 API 同样获得登记档案来源支持。

已登记档案作为来源时，仅提供保存的原文摘录并绑定档案字节、原件登记摘要及页码；原件没有重开时明确记录，不能声称复核了 PDF。`specs` 映射、`owner-confirmed`、搜索摘要和用户想表达的卖点均不直接获得事实资格。不接受请求正文指定本地文件路径或任意档案内容。

本任务不修改网络来源的 SSRF 规则，不直接绕过 G1 调用供应商，不制造镜头卡或审批，不更改发布规则。完整出片仍走既有管线，恢复制作时显式指定单次渲染上限并复用已验收角色资产。

## 运行接口与故障路径

CLI 新增 `--product-archive <登记id>`、`--metadata-file <JSON对象>`、`--tenant`、`--workspace`；角色与参考素材元数据保留，用户传入的完整商品档案必须与正式库一致。每次运行与显式重试使用新的运行/attempt，完整来源、G1 审查及逐镜事实绑定本次作用域。缺省不重试，业务失败退出 4 并保存未提交渲染的失败记录。叙事分流保持原有行为。

来源支持函数只允许正式库 id，拒绝路径、符号链接、档案/图片摘要变化、商品型号或品牌不匹配。证据正文仅取保存的原文摘录；不支持任意本地 PDF 或用户请求正文充当事实。原 PDF 未重开会保留 `originalReopened=false`。HTTP 来源的私网地址与重定向限制保持有效。发现记录先落盘，再返回 A1 来源错误；G1 裁决保存后才能发出 `verifiedRaw`。

CLI 接线回归放在 server 测试范围，由现有 `test-gate` 执行，不增加或绕过流水线规则。
