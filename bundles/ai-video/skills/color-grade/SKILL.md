# 调色执行纪律

## 默认执行顺序（2026-10-07）

1. 读取实际所需规格与源文件摘要，确认文件可供加工；不加新的全帧验收或抽样品质审核。
2. 按本次请求与题材/平台元数据选择固定配方。`grade` 的 `auto` 不先分析源画面；`best` 使用确定性请求配方，无品质候选评分或自动判无需加工。
3. 以实际 profile/LUT、强度与滤镜链加工一次，输出新文件。
4. 留源/产物摘要、实际参数、规格与工具回执；`qualityReviewed=false`，未测品质值为 `null`。

## 创作选型建议

| 内容 | profile 建议 | 强度建议 |
|---|---|---|
| 叙事/情感 | `warm-film` | 0.7–0.85 |
| 产品/教学 | `clean-bright` / `natural` | 0.6–0.8 |
| 技术 | `cool-technical` | 0.6–0.75 |
| 悬疑 | `moody-dark` | 0.5–0.7 |
| 社媒 | `high-contrast-social` | 0.7–0.85 |
| 怀旧 | `vintage-fade` | 0.6–0.75 |

这些是参数建议，不能变成源片曝光、肤色、模糊、噪点、色带、画質或可见性的品质否决，也不触发重渲染。用户明确参数优先；非法值按输入合同失败。

## 显式诊断与匹配

`colorread.analyze` / `colorread.scope` 保留为显式诊断，报告可追溯，不被默认生产调用。`colorwrite.match` 仅在明确要求参考匹配时读取相关数据并实际加工；诊断残差不追加默认品质审查。

## 输出契约

实际源/产物路径与 SHA-256、滤镜链、profile/LUT、强度、实际规格、工具指纹及源字节未改事实。未执行的分析、缺陷、scope、前后差异填 `null` / 空列表并标 `qualityReviewed=false`，不能补造品质通过。

## 权限与失败

原片只读（G-COL2）、租户/路径/字节、品牌 look 前置授权（G-COL1）和配额（G-COL4）保持。G-COL3 仅阻实际产物缺失或源字节变化，不因旧 `verify` / `skip_verify` 开关阻挡。真实缺 LUT/文件/引擎、非法参数、存储或 FFmpeg 错误明确失败留痕，不把失败变成成功、不通过品质判断重生成。

历史 `library/color-kb/` 供显式诊断参考，其旧评分与硬阈值不适用于当前默认后期。
