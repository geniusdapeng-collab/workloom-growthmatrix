# 封面设计

## 当前正式工位口径（2026-10-07）

封面服务把成功视频里的请求时刻变成用户需要的封面。`post-bridge/core.mjs#buildCover` 固定取一次帧，按请求画布缩放/补边，用字幕工位同源 ASS 和实际随仓字体写标题，再渲染一次 PNG。请求的变体使用自己的标题/副标题、字体布局与时刻，清单留下真实配方和文件。

成功源片默认接受。人物、服装、动作、原始黑画面、规格、对白/口型不参与封面放行；不抽多个候选帧选优、不调设计/品质模型、不做人物抠像必需层或人物造型比对，也不以 PSNR、墨迹、遮挡/安全区分数触发退回或重渲染。`qualityReviewed=false` 表示未做品质审核，不能改称品质已合格。

## 输入与动作

| 输入 | 实际作用 | 缺失或错误 |
|---|---|---|
| 已有成功视频 `input` | 供 FFmpeg 实际取一帧，保留原文件 | 缺文件、不可读取、无有效视频元数据或实际解码失败时失败 |
| `resolution` / `platform` | 决定实际输出画布与字体配方 | 最终请求尺寸不符时返回技术失败 |
| `project.copy.title` / `project.title` | 实际主标题；项目标识为既有末级回退 | 不能把未提供的用户文案编成用户事实 |
| `variant.cover.at` | 按片长比例计算请求时刻，限在可读取范围 | 记录 `requestedAt/selectedAt`，不声称最佳画面 |
| `variant.cover.subtitle/alignment/marginRatio` | 按本次请求实际渲染副标题与布局 | 非法字体/ASS/引擎参数按真实错误失败 |
| 随仓字体 | 从 `library/fonts/{cn,en}` 装载实际字体 | 字体缺失或渲染进程失败，不返回假成功 |

1. 读取当前视频元数据，记录源帧与来源文件。
2. 在请求时刻取一帧；该取帧用于制作封面，不用于源片品质判定。
3. 生成 ASS；使用实际字体和请求画布渲染一次 PNG。
4. 读取实际 PNG 的宽高、大小与 SHA-256；把时刻、字体、配方、路径、摘要写进后期回执。
5. 同一源片可用于用户请求的多个变体，保持源文件字节；不要求变体间像素差或封面人物差异分数。

## 设计建议

标题大小、对齐、留白和清晰阅读是专业设计建议，可通过明确修改 `cover.*` 配方进行本地返修。默认工位使用现有平台字体与布局配方；实际需求的长标题或单字成行不触发源片品质拒绝。用户明确要求新的封面设计时，在现有素材上改封面层，记录修改项和新文件；只有用户明确点名更换画面内容时才提出新的镜头生成计划与花钱门。

## 回执与失败

回执包含 `output/at/requestedAt/frame/assPath/fontsDir/width/height/sha256/bytes/checks`。它证明实际取帧、渲染和文件事实，不能证明图片好看、身份一致或点击率提升。`clean-source` 不再通过逐帧/PSNR 源片比对放行；原文件 SHA-256 与实际命令记录供来源复核。

| 情况 | 处置 |
|---|---|
| 来源缺失、摘要被改或真实供应商失败 | 保留失败回执，不把它当成功源片、不提交品质重渲染 |
| FFmpeg/ASS/字体失败或 PNG 未产出 | 原样返回实际技术错误，只修对应后期工位 |
| 请求尺寸、文件路径或取件摘要不符 | 重新核对本次导出，保留旧记录 |
| 用户修改标题、时刻或布局 | 改封面层并产出新版本，复用成功镜头 |
| 用户明确要求更换镜头画面 | 出逐镜计划，先过新生成授权与支付门，再走正式后期 |
