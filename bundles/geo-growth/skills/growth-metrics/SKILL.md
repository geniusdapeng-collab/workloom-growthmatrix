# 增长线指标口径（五项周表）

## 适用场景
- 周一全网存在感战报的「增长栏位」出表，以及月度回测、复盘报告引用增长数据；
- 投放/内容/达人复盘要回答「粉丝、互动、私域、复购、转介到底涨没涨」；
- 客户或内部对同一指标出现两个数时，作为唯一口径解释源（先对口径，再谈业务结论）；
- P3 双场景日更阶段：增长五项周表连续 2 周可复算（M3 里程碑）。

## 触发条件
- 每周一 09:00 `report.weekly`（触发器 `tg-geo-battle-report`，含增长栏位）；
- 增长实验结项、预算再分配、月度回测（`backtest.run`）需要引用增长事实；
- 任一指标相对 4 周基线波动 ≥20%，或平台后台改版导致口径待确认。

## 输入数据
- 分平台分账号时序：`account_growth_metric` 对象（粉丝/播放/互动/收藏/转发），按「平台 × 账号 × 日」落账；
- 私域台账：企微好友新增/流失、社群净入群（按唯一外部联系人去重）；
- 线索与成交：`inquiry` / `lead` / `conversion`，成交以核销口径为准；
- 成本账：投放消耗、内容与达人费用、工具分摊（`budget_ledger`）；
- 数据边界：只取脱敏聚合数，客资明细（手机号/微信/对话原文）不上表、不出域（G-GROW6）。

## 方法（五项固定分子分母 + LTV/CAC）
1. **粉丝净增**：分子 = 期末粉丝数 − 期初粉丝数；分母（净增率）= 期初粉丝数。窗口 [上周一 00:00, 本周一 00:00)，按平台 × 账号分列；期初为 0 的账号只报绝对净增并标注「新账号」，不计算比率。
2. **互动率**：分子 = 周内点赞 + 评论 + 收藏 + 转发 + 分享（按平台后台可得动作取并集，同一次互动不重复计）；分母 = 周内播放量；无播放口径的平台改用曝光，须在表注标明。账号级与组合级一律**先加总分子分母再相除**，不平均日率。
3. **私域沉淀率**：分子 = 周内新增私域可触达人数（企微好友净增 + 社群净入群，按唯一外部联系人去重，流失在分子中扣减）；分母 = 周内内容触达人数（分平台去重后总触达，口径与平台后台一致）。
4. **唤醒转化率**：分子 = 唤醒实际送达后 7 日内有效转化数（到店/核销/成交，同一客户多次转化只计一次）；分母 = 唤醒实际送达人数（发送失败、退回、未送达不计入）。转化跨周发生时按转化发生周归集，并在表注披露回溯窗口。
5. **复购转介**：复购率 分子 = 周内有成交且历史累计成交 ≥2 次的客户数，分母 = 周内活跃成交客户数；转介绍率 分子 = 周内由老客转介绍的新客数，分母 = 周内新客总数；两率并列展示，不合并成单一指数。
6. **LTV/CAC**：LTV 分子 = 12 个月窗口客户毛贡献（核销口径，扣退款与取消），分母 = 该客群客户数；CAC 分子 = 同期获客总成本（投放 + 内容生产 + 达人 + 工具分摊），分母 = 同期新增有效客户数（留资不算有效客户；有效 = 已成交或按一店一档认定的高意向）。比值 = LTV / CAC，**低于 3 倍进预警**（客群覆盖层可收紧阈值，不可放宽）。

## 边界（什么不做）
- 不用日率平均代替周率、不把平台比率再加权平均（除加权平均且权重与口径一并披露）；
- 不混用曝光与播放分母、不把不同平台口径揉成一个数（必须分平台分账号列示）；
- 不把下单/支付当成交（成交只认核销）；不把自然增长记入投放增量（增量结论走 `incrementality-measurement`）；
- 不导出客资明细、不上表手机号/微信号/对话原文；平台未回传的数据标「未核实」，不补零、不估算。

## 决策原则（含阈值与失败关闭）
1. **口径冻结 + 版本号**：周表必须带 `metricsVersion`（与技能版本一致），五项指标逐字使用本节分子分母；任何改动先双跑一周并留痕评审，双跑期旧口径只读保留。
2. **先加总后相除**：账号级/组合级比率一律先加总分子与分母再相除；违反即视为口径错误，重算后才可出表。
3. **核销口径优先**：成交类指标只认核销（下单/支付不计），退款与取消在分子中扣减；无法核销的平台标「未取数」，不得用下单数顶替。
4. **缺失即失败关闭**：应出表平台/账号缺数 → 该行标「未核实」且不得进入「达标」结论；分平台覆盖率 <100% 时，周报增长结论必须降级为「部分可判定」并附补采单。
5. **数据边界不可破**：只出聚合数，客资明细不上表、不出域（G-GROW6）；对外导出与共享走审批，脱敏规则不因「方便核对」放宽。
6. **异常先查口径**：波动 ≥20% 时先做采集完整性与口径变更稽查，排除口径原因后才允许归因给内容/投放/市场。

## 打法库（场景 → 动作序列 → 判据）
- **主线·周一增长五栏**：`report.weekly` 触发 → 拉取近 7 天 `account_growth_metric` + 私域/成交台账 → 按五项口径计算 → 与战报三栏（社媒/GEO/交叉）对账 → 输出周表 + 口径版本 + 样本量（判据：五项齐全、分平台覆盖率 100%、差异 ≤1%）。
- **分支·异常波动（±20%）**：对比 4 周基线 → 先查采集缺口与口径变更 → 再查内容/投放动作 → 输出「口径结论 + 业务结论」两段（判据：两段分开写，未排除口径前不写业务归因）。
- **分支·平台改版/口径争议**：新旧口径双跑一周 → 周表并列两列并标切换日期 → 评审通过后下掉旧列（判据：双跑记录与切换决议可查）。
- **分支·P2 条件岗未激活**：生命周期与私域深度指标由 `guest-success` + `private-domain-operator` 承接；`lifecycle-growth` 未激活时（G-GROW7）不得把产出记到该岗名下。

## SOP（每步带触发/回执/失败路径）
1. **采集**（触发：周一 09:00 / 实验结项）→ 拉取分平台分账号时序与私域/成交台账 → 回执：数据快照 ID + 覆盖清单；失败：平台或账号缺数 → 标「未核实」并开补采单（不补零、不估算）。
2. **计算**（口径版本 vX）→ 按五项分子分母 + LTV/CAC 计算 → 回执：周表（分子/分母/比率/样本量/口径版本）；失败：分母为 0 或样本不足 → 标「不可判定」，不输出比率与结论。
3. **对账**（与 `biz_events`、战报三栏、财务核销数交叉）→ 差异清单与原因 → 回执：差异率与处理记录；失败：差异 >1% → 阻断外发，先修数据或口径再重跑。
4. **交付与归档**（周一战报增长栏 + 月度回测）→ 引用记录与口径版本入库 → 回执：引用链（表 → 报告 → 决策）；失败：未过对账的周表不得进入客户外发件。

## 关键指标（含基准与护栏）
| 指标 | 口径 | 基准/阈值 | 类型 |
|---|---|---|---|
| 五项周表可复算率 | 可复算指标数 / 应交指标数 | 100% | 治理 |
| 分平台覆盖率 | 有数据平台数 / 应出表平台数 | 100% | 质量 |
| 未核实标注率 | 如实标注缺失项 / 应标注缺失项 | 100% | 治理 |
| 口径版本一致率 | 表内 metricsVersion 与技能版本一致的表数 / 全部周表 | 100% | 治理 |
| 五项连续可用周数 | 五项齐全且可复算的连续周数 | ≥2 周（P3 门槛） | 业务 |
| LTV/CAC | LTV ÷ CAC（核销口径） | ≥3；<3 预警 | 业务 |

## 失败模式（症状 → 检测器 → 处置）
| 症状 | 检测器 | 处置 |
|---|---|---|
| 用日率平均当周率 | 口径审计（先加总后相除检查） | 重算并更正周表，记录错题 |
| 曝光/播放分母混用 | 分母列校验 | 分平台分列重算，重新对账 |
| 下单/支付当成交 | 核销口径对账 | 改核销口径重算，撤回结论 |
| 缺数补零或估算 | 覆盖率与快照检测 | 撤回补零、标「未核实」、开补采单 |
| 客资明细进表/出域 | 数据边界扫描（G-GROW6） | 立即删除并回滚外发，按事件留痕 |
| 口径变更不做双跑 | 版本号与双跑记录比对 | 暂停使用新口径，补双跑一周 |
